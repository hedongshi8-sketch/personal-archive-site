## 1. 当前 Demo 截图问题清单

### 1.1 画面为什么显得简单

从默认截图和入口证据截图看，当前画面主要问题不是“没有素材”，而是缺少视觉构成：

- 地面是大面积单色矩形块，区域边缘是硬切，没有草边、碎石、泥路、台阶、田埂、水岸、阴影等过渡。
- 物件像测试点散落在平面上，缺少物件簇。例如灵泉旁没有水边植被、石灯旁没有光晕、茶摊没有桌椅/招牌/摊位关系。
- 没有前景遮挡和 Y-sort 层次，玩家和物件都像贴在同一张纸上。
- 没有角色脚下阴影、物件阴影、灯光、环境暗部，空间厚度不足。
- HUD 已比旧版克制，但底部说明仍偏“操作提示条”，缺少与场景内对象联动的交互提示。
- 场景没有明确视觉焦点：洞府、灵田、裂岩、茶摊、灵泉、断桥都在同一优先级上，玩家第一眼不知道哪里重要。

### 1.2 交互为什么像测试触发器

脚本已经支持多个入口、菜单和 Debug Overlay，但交互反馈仍主要靠 toast 文字：

- 靠近对象只有文字提示，没有对象描边、轻微亮度变化、浮动符纹或方向性反馈。
- 显形、爆炸、护体、元神、传音的结果主要是文字说明和 tint 改色，没有足够的动画、粒子、音效、对象状态变化。
- 资源点采集后缺少“采前/采中/采后”状态，无法形成世界持久变化。
- NPC 缺少 idle 动画、转向、表情/气泡、行走或情绪变化。
- 地图没有微循环：风动、灯闪、水波、草摇、灵气粒子、尘土、烟雾都缺席。

## 2. 高级像素画面由哪些层组成

高级像素画面不是分辨率高，而是层次明确、信息可读、动静有节奏。

| 层 | 最低要求 | 对本项目转译 |
| --- | --- | --- |
| 地面基础层 | 草地、土路、石板、水岸、室内地板有材质差异 | 洞府地板、庭院泥土、山门石路、灵泉水岸分开 |
| 边缘过渡层 | 区域交界不用硬矩形，用草边、阴影、石沿、台阶过渡 | 灵田田埂、洞府门槛、断桥边缘、药铺门前路 |
| 装饰密度层 | 物件按簇组织，不孤立摆点 | 茶摊=桌椅+灯笼+招牌+茶客；灵泉=水波+石边+草丛+微光 |
| 前景遮挡层 | 树冠、屋檐、岩壁、门框可遮挡角色 | 洞府门框、药铺檐、山门树影 |
| Y-sort / 高度层 | 角色可从物件前后穿行，遮挡关系正确 | NPC、石灯、树、岩障、桥台使用 Y-sort |
| 阴影层 | 角色脚影、物件投影、墙角暗部 | 所有角色和大型物件有接地感 |
| 光照层 | 灯、灵泉、符阵、夜色有光源 | 石灯黄光、灵泉蓝光、符阵紫光 |
| 粒子/天气层 | 尘土、水波、萤火、灵气、叶片 | 灵气漂浮、符纸灰、爆炸尘土、传音波纹 |
| 动画循环层 | 水面、火光、草、NPC、作物有循环动画 | 灵田呼吸、灯火闪烁、茶客动作 |
| 镜头构图层 | 重要对象落在视线引导线上，画面有入口和深处 | 洞府到庭院到山路形成阅读路径 |
| 色彩分区层 | 区域用色相/明度分层，不糊成一片 | 洞府暖、灵泉冷、废阵紫、山路灰绿 |

## 3. 高级交互由哪些反馈组成

每个关键交互至少要有“前中后”三段反馈。

| 阶段 | 反馈类型 | 示例 |
| --- | --- | --- |
| 靠近前 | 环境暗示 | 裂岩有细缝、符阵有断线、灵泉冒光 |
| 靠近时 | 可交互反馈 | 物件轻亮、符纹浮现、角色看向对象 |
| 输入瞬间 | 动作反馈 | 角色抬手、符纸飞出、丹炉开盖 |
| 生效中 | 动效/音效/粒子 | 光纹扩散、尘土、震动、水波、风声 |
| 生效后 | 世界状态变化 | 岩障碎裂留场、隐藏路出现、NPC换位置 |
| 归档 | 主动菜单记录 | 札记新增“裂岩可被爆符震开” |

## 4. 参考作品的具体启发

### Stardew Valley

适合学生活模拟场景密度和可读性：农田、道路、建筑、树木、NPC路线、季节资源共同让场景有生活秩序。不要照搬农场日课；要学“玩家看一眼就知道哪里可走、哪里可交互、哪里有长期目标”。

### Eastward

官方资料称其为“beautifully detailed pixel art adventure RPG”，并强调双角色、环境谜题、奇异城镇和强声音表现。适合学像素场景的细节密度、角色动作、城镇生活质感。不要照搬线性剧情推进；要学小场景里的物件簇和视觉焦点。

### CrossCode

Steam 页面强调 16-bit 风格、顺滑物理、快节奏战斗和谜题机制。适合学“手感来自动作、碰撞、反馈和谜题对象状态”，不是只给文字。不要照搬高强度战斗；要学能力和对象之间的即时反馈。

### Little Witch in the Woods

官方/商店资料强调女巫日常、森林探索、采集、制药和帮助居民。适合学魔法生活模拟的氛围：植物、家具、居民、猫、药水、森林细节。不要照搬女巫题材；要转译为洞府、灵田、丹房、药谷。

### Potion Permit

Steam 页面强调照顾居民、诊断、采集材料、制作药剂。适合学“角色需求 -> 世界采集 -> 制作 -> 居民变化”的小循环。不要照搬医疗主题；要转译为门派弟子、药铺、炼丹、身体状态。

### Core Keeper

官方/商店资料强调采矿、建造、战斗、制作、农场和基地。适合学地下空间的光照、采掘反馈、环境持久变化。不要照搬生存刷资源；要学矿脉、岩障、灵泉、废阵如何被交互后改变场景。

### The Legend of Zelda: Breath of the Wild

GDC 演讲适合继续作为环境规则反馈参考：玩家通过环境对象响应理解规则，而不是靠说明文字。不要照搬开放世界规模；要学“火、电、风、重量”等响应方式如何变成修仙里的“灵气、符纹、风口、灵泉、阵眼”。

## 6. 后续 Demo 最低验收标准

### 6.1 画面结构硬门槛

- 至少 5 层 TileMap/视觉层：地面、过渡/道路、装饰、遮挡/Y-sort、特效/光照。
- 至少 4 个区域有明确色彩分区：洞府、灵田、山门、灵泉/废阵。
- 至少 20 个非重复装饰物件按簇摆放，而不是孤立测试点。
- 每个大型物件有接地阴影或遮挡关系。
- 至少 3 个局部光源：石灯、灵泉、废阵/符纹。
- 默认截图不能出现大面积硬矩形色块地图。

### 6.2 动画与特效硬门槛

- 角色至少有 idle + 4向移动动画。
- 至少 5 类环境循环动画：水波、灯火、灵气、草/叶、NPC idle。
- 至少 4 类交互特效：显形光纹、爆炸尘土、元神轮廓、传音波纹。
- 至少 3 个对象有交互前/后状态变化：裂岩、灵田、阵眼/空气墙。
- 至少 2 处短镜头反馈：轻微震动、短暂停顿或镜头跟随变化。

### 6.3 交互与小循环硬门槛

- 每个核心能力至少有一个可见对象响应，不只显示文字。
- 至少 2 条入口路线能产生不同发现：环境入口、人物入口、修行入口、元神入口中至少两条成立。
- 交互结果必须持久留在场景里，不能只弹 toast。
- NPC 至少有称呼/朝向/一句状态变化，不只是静态按钮。
- 札记只归档发现，不替代场景反馈。

### 6.4 证据硬门槛

- 至少提交 4 张截图：默认画面、显形前后、爆炸前后、元神/传音状态。
- 至少提交 1 段 30-60 秒短录屏或逐帧说明，证明交互反馈链成立。
- README 必须列出资产来源、许可、导入设置、截图路径和操作方式。
- 工程结构必须拆层：地图层、对象层、交互层、特效层、UI层、Debug层。

### 给 Demo验收模块 `REV-20260804-12`

请把工程从“脚本生成一批 Sprite 测试点”升级为：

- TileMapLayer / TileSet 多层地图。
- Y-sort 对象层。
- AnimatedSprite2D 角色/NPC。
- AnimationPlayer 负责交互状态变化。
- GPUParticles2D / CPUParticles2D 负责灵气、尘土、波纹。
- PointLight2D / CanvasModulate / LightOccluder2D 做局部光影。
- Camera2D 做轻微跟随、震动和构图。
- CanvasLayer 只承载克制 HUD 和菜单，Debug 默认关闭。

## 8. 结论

高级像素 Demo 的关键不是“更多素材”，而是画面层级、物件组织、动效反馈和世界持久变化。下一轮必须把《我的修仙日常》从“可点击测试场”提升为“一眼像游戏、动起来有手感、交互后世界会变”的开放小区域样本。
