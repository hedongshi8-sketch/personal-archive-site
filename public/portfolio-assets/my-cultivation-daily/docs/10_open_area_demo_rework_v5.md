# 《我的修仙日常》开放小区域Demo重构规格 v5

## 1. Demo定位

Demo 是**大世界修仙生活模拟的开放小区域样本**，不是线性教学关。

它要验证的是：玩家在同一片小区域内，能否从不同入口获得不同理解，并把这些理解交叉起来。

## 2. Demo应该长什么样

Demo 不是一条固定路线，而是一张可回访的小区域。

建议结构：

- 一个起始生活点。
- 一个环境异常点。
- 一个人物活动点。
- 一个修行实验点。
- 一个元神观察点。

这些点可以互相覆盖，也可以互相回流，但不要求按顺序走完。

## 3. 四类自由入口

### 3.1 环境入口

玩家先观察世界：

- 风向。
- 地脉。
- 岩障。
- 灵泉。
- 断桥。
- 天气和昼夜。

可得到：

- 隐藏层。
- 可破坏对象。
- 路径。
- 异常点。

不能变成：

- 单纯任务箭头。
- 一眼看穿的唯一答案。

### 3.2 人物入口

玩家先接触 NPC：

- 茶客。
- 药铺老板。
- 符观残道人。
- 过路散修。

可得到：

- 传闻。
- 误导。
- 交易。
- 态度变化。
- 人物之间的冲突和立场。

不能变成：

- 任务广播机。
- 唯一推进器。

### 3.3 修行入口

玩家先从修行状态切入：

- 试符。
- 试药。
- 炼丹失败。
- 调息。
- 受天气或地脉影响。
- 复盘旧经验。

可得到：

- 感悟。
- 状态变化。
- 札记新增。
- 新的观察方式。

不能变成：

- 蒲团专属按钮。
- 经验条式领奖。

### 3.4 元神入口

玩家先从元神视角切入：

- 在安全地点短时出窍。
- 远观。
- 侧听。
- 看见隐藏层或残响。

可得到：

- 物理视角看不到的信息。
- 残缺或完整的传音。
- 环境中的灵性痕迹。

不能变成：

- 蒲团专属模式。
- 万能侦查按钮。

### 3.5 核心能力样本入口

Demo 虽然只做开放小区域，但也必须表达“能力线索与能力理解可多源获得”。不要把它写成一条固定教学链。

| 能力 | 样本入口 A | 样本入口 B | 深化表现 |
| --- | --- | --- | --- |
| 显形 | 符观残纸、残道人口述 | 庭院石灯异常、空气墙显纹 | 在不同对象上反复显形，理解隐藏层 |
| 爆炸 | 裂纹岩、封石、旧爆符 | NPC交易、野外误触、试错 | 学会分辨可炸与不可炸 |
| 护体 | 受击危机、灵压压迫 | 雷雨、炼丹失控、阵法边缘 | 理解护体时机和代价 |
| 御剑 | 高台剑痕、远处剑鸣 | 断桥风流、门派旧试剑痕迹 | 只埋线索，不做完整开放 |
| 丹药 | 药铺试药、草药采集 | 炼丹失败、身体状态异常 | 通过药性和身体反馈深化理解 |
| 元神 | 安全地点短时出窍 | 夜路侧听、阵眼观察、灵泉旁试探 | 通过距离和环境扰动理解边界 |
| 传音 | 茶摊偷听、NPC闲聊 | 风口回响、阵法折射、残碑回音 | 肉身与元神听到的信息不同 |

## 4. Demo必须证明的事

Demo 不需要证明“系统全做完了”，只需要证明：

1. 世界有规则。
2. 规则可以从不同入口被理解。
3. 同一问题可以有多条路线。
4. 感悟不是蒲团独占。
5. 元神不是蒲团独占。
6. 传音不是唯一线索。

## 5. 推荐的开放小区域样本

### 5.1 地图样本

可用一片小区域承载四类入口，例如：

- 洞府/静室。
- 庭院灵田。
- 山门小径。
- 茶摊或药铺。
- 断桥视域。
- 一处灵泉或阵眼。

这些点不需要按顺序解锁，而是允许玩家自由前往。

### 5.2 共同现象

同一个现象最好至少有两种以上入口可触达，例如：

- 隐藏灵脉可从环境观察看到，也可通过显形或元神看到。
- 岩障可从环境推断，也可从 NPC 传闻推断，也可通过试符验证。
- 传音可在肉身听片段，也可在元神听完整。
- 感悟可来自失败，也可来自观察，也可来自复盘。

## 6. 结尾不应是唯一结局

Demo 的收束方式应是“样本总结”，而不是“打完这一关”。

可接受的收束方式：

- 玩家自己返回洞府复盘。
- 玩家打开札记看见已确认的规则。
- 玩家在任一收束点得到阶段总结。
- 玩家确认自己已经理解了若干规则，但世界仍有更多未解之处。

不应出现：

- 唯一正确结尾。
- 唯一固定顺序。
- “不按这个顺序就无法理解”的设计。

## 7. Demo验收重点

验收不看是否按顺序通关，而看是否存在多入口、多结果、多回流。

最低应满足：

- 环境入口成立。
- 人物入口成立。
- 修行入口成立。
- 元神入口成立。
- 不要求四条都串成一条线，但要都能独立发生价值。

## 8. 给制作员的直接改法

1. 删除线性教学链的表达。
2. 将地图目标改成开放样本点。
3. 把传音改成信息生态，不再是唯一任务广播。
4. 把感悟改成可随时触发的复盘结果。
5. 把元神改成自由尝试但受条件限制的能力。
6. 保留 UI/UX v4 的主画面克制原则。

## 9. 结论

Demo 不是“教会玩家一条路”，而是“让玩家看见世界可以有很多路”。
