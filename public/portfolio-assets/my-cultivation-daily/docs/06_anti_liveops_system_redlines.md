# 《我的修仙日常》反运营化系统设计红线

## 任务信息

- 项目ID：`P-20260802-我的修仙日常`
- 任务编号：`REV-20260803-02`
- 用途：给系统体验模块下一轮重写使用，避免继续把单机项目做成小程序 / 运营游戏结构。

## 最高判定

本项目是**单机独立游戏 / 买断式体验优先**。系统设计必须服务沉浸、发现、空间理解、规则复用和长期口碑，不服务留存、活跃、转化、打卡或资源消耗KPI。

## 必须禁止

| 禁止项 | 为什么禁止 | 可替代方向 |
| --- | --- | --- |
| 每日签到 | 把玩家动机从“想进入世界”改成“怕错过奖励” | 用季节、天气、NPC约定自然制造回访 |
| 活跃度 | 把体验压成任务清单和进度条 | 用空间变化和关系变化反馈玩家行动 |
| 登录奖励 | 典型运营留存钩子，破坏买断式体验 | 用世界内事件和信件表达时间流动 |
| 强制日课 | 让玩家每天重复清单，不像自由生活 | 允许玩家选择今天修炼、种田、拜访或探索 |
| 体力卡点 | 若只为限制游玩，会像商业化节流 | 可保留“身体状态”，但必须有叙事和策略理由 |
| 资源KPI | 让设计围绕产出、消耗、回收，而不是体验 | 资源只服务空间、关系、解法和阶段仪式 |
| 功能菜单堆叠 | 把修仙名词变成按钮合集 | 能力应落在物体、空间、NPC和事件里 |
| 第一天开放全部系统 | 破坏发现感和递进 | 先给一套母题，再逐步长出符箓、丹药、御剑等用法 |
| 纯数值境界 | 修仙变成经验条领奖 | 境界突破应是准备、理解、仪式和风险 |
| 任务引导过度 | 玩家只会执行，不会发现 | 用可观察对象、环境反馈和NPC暗示引导 |

## 判断一个设计是否跑偏

如果一个提案出现以下信号，应判定为运营化风险：

- 需要玩家每天固定上线才能不亏。
- 系统目标可以被“完成 X 次、领取 Y 奖励”概括。
- 主要反馈来自弹窗、红点、进度条、任务面板。
- 空间没有变化，只有数值变化。
- NPC 只是任务入口。
- 能力只是快捷按钮，不改变玩家看世界的方式。
- 所有系统都能在菜单中完成，不需要玩家走到具体地点。

## 《我的修仙日常》的正向替代

| 运营化表达 | 单机化替代 |
| --- | --- |
| 每日修炼任务 | 今日灵气状态、身体状态和环境变化带来的自然选择 |
| 签到领奖 | 师门信件、NPC约定、节气事件 |
| 活跃度宝箱 | 洞府新路径、NPC信任、禁制松动 |
| 体力限制 | 气息紊乱、心境不稳、灵气过载等可理解状态 |
| 功能按钮 | 可被灵气作用的物体、符纸、丹炉、飞剑、传音石 |
| 资源消耗循环 | 为突破、帮人、修复空间、解决问题而准备材料 |

## 下一轮系统方案最低要求

系统体验模块 `REV-20260803-03` 至少应做到：

1. 写明本项目不是运营游戏。
2. 删掉签到、活跃度、登录奖励、强制日课。
3. 把所有能力统一在“灵气作用方式”下。
4. 用空间和对象承载系统，不用功能菜单承载系统。
5. 给出至少一个多解法场景。
6. 给出清晰的第一小时解锁顺序。
7. 用“玩家发现”替代“任务要求”。

## 结论

本项目要做的是“修仙生活的可理解世界”，不是“修仙素材包装的运营框架”。任何不能增强玩家发现感、空间感和规则美感的系统，都应先删掉，而不是继续堆功能。
