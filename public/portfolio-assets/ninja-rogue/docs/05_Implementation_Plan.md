# 05 Demo 到落地计划

## 阶段 0：作品集 MVP

周期：2026-07-29 至 2026-08-02

目标：

- 完成系统设计文档、PRD、美术需求、配表和 Unity 2D 水墨风占位 demo。
- 让面试官能在 3 分钟内看懂核心循环。
- 重点证明系统策划的拆解、抽象、表达和验证能力。
- demo 首屏语言必须中文化，不能出现面向中文投递的英文占位 UI。
- 原型必须能看出角色差分、武器差分、单跑道上下切位、关卡差分、左右门和中央祭坛关系。

交付：

- Unity 工程
- 一键场景生成器
- 配置 JSON
- CSV/Excel 配表
- 第三方相近占位素材来源说明
- Word 总文档
- 作品集讲述文案

## 阶段 1：玩法验证版

周期：2026-08-03 至 2026-08-12

目标：

- 加入真实跑酷判定：跳跃、下滑、索道/钩锁或替代移动。
- 加入武器释放输入、冷却、伤害、单跑道上下切位压力和障碍清理。
- 增加至少 8 个房间模板。
- 记录局内选择路径。

验收：

- 3 名玩家可以无说明完成一局。
- 玩家能说出自己这局的构筑方向。
- 至少 70% 的玩家能在第一次终点理解两个门的区别。

## 阶段 2：数值平衡版

周期：2026-08-13 至 2026-08-22

目标：

- 完成角色、武器、协同、房间难度权重表。
- 加入奖励池权重、保底和去重。
- 加入低保构筑：连续 2 次无同标签奖励后，提高相关标签权重。
- 完成失败复盘数据。

验收：

- 每局至少激活 1 个两件协同。
- 强势流派和保守流派通关时间差距控制在 20% 到 30%。
- 随机奖励不出现明显死局。

## 阶段 3：包装与投递版

周期：2026-08-23 至 2026-08-31

目标：

- 做 60 到 90 秒演示视频。
- 整理 4 页作品集 PDF：立项、核心循环、配表/PRD、demo 截图。
- 准备 90 秒面试口述。

验收：

- 首屏能看懂“忍三 x 小骨 x 系统策划”。
- 每个系统决策都有数据字段或 demo 对应。
- 不出现版权风险素材。

## 正式落地依赖

- 需要确认活动入口和主界面 UI。
- 需要确认可复用的正式角色/武器资产列表。
- 需要程序接入正式跑酷框架、战斗框架和结算框架。
- 需要数值策划提供正式武器参数或转换规则。
- 需要 QA 覆盖随机种子、奖励池、槽位替换、断线重连和结算发奖。

## 风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| 随机性导致构筑不可控 | 玩家拿不到同标签奖励 | 加入权重递增和保底 |
| 双角色切换学习成本高 | 玩家忘记切换 | 教学首局强制演示，HUD 显示冷却和入场技能 |
| 武器过多导致阅读压力 | 奖励卡文字过长 | 每卡只保留一句效果，详情进二级页 |
| 与长期养成冲突 | 高练度玩家优势过大 | 活动局内使用标准化临时数值 |
| 版权风险 | 作品集使用原图资源 | demo 不使用忍三/Skul 商业素材；第三方占位素材必须保留来源和授权核验；正式接入必须走授权资产库 |
